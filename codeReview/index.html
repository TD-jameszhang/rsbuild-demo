Code Review ​

原文: https://github.com/google/eng-practices/blob/master/review/reviewer/looking-for.md

CodeReview时,我们需要Review哪些些内容? ​

Design(设计) ​

最重要的内容,应该是 Change List, 即当前PR提交的代码,所修改的点,以及它的架构设计原理等.

  • 它所修改的各代码段是否有意义?
  • 它与其他子系统是否能够良好的集成?
  • 现在添加这个新功能, 是最好的时机吗?
  • ...

Functionality(功能性) ​

  • 这个CL是否达到了开发者的预期?
  • 这段代码的目的, 对用户来说,有什么好处?
    • 用户, 即是最终用户, 也可以是其他开发人员
  • 是否已通过 eslint 检测?
  • 已通过 unit test?
  • 有没有其他边界没有考虑到?
    • 边界问题?
    • 并发问题?
  • 核心的功能 或 影响较大的功能, 开发者能否演示这代码修改的点? 以供 代码审阅者 理解代码的影响(特别是UI交互的影响)

Complexity(复杂度) ​

太复杂: 即代码阅读者很难快速阅读代码,理解代码的含义. 同时, 也意味着,开发人员在尝试调用或修改这些代码时,可能会引入错误.

  • CL中的功能实现,是否必须要这么复杂?
    • 单行代码是否太复杂?
    • 函数是否太复杂?
  • 一些特殊场景的功能过于复杂,很有可能是过度设计(例如下面的场景). 代码审阅者应对过度设计特别警惕,鼓励开发人员解决当前所需要解决的问题, 而不是推测将来可能需要解决的问题.
    • 代码功能过于通用?
    • 添加了系统当前不需要的功能?

Testing(测试) ​

根据CL, 添加 单元测试/端到端测试.

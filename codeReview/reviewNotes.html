多余的函数入参 ​

传入多余的参数, 可能会:

  • 降低代码的可读性和可维护性：
    • 多余的参数会使函数签名变得复杂，其他开发者在阅读代码时可能会对这些参数的用途感到困惑。
    • 如果这些参数的来源不明确，可能会增加理解代码逻辑的难度。
  • 增加调用者的负担：
    • 调用者需要提供这些不必要的参数，即使它们可能并不清楚这些参数的具体作用。这会使代码的使用变得不那么直观和方便。
  • 可能导致错误：
    • 如果调用者错误地提供了参数值，可能会导致函数的行为不符合预期。
    • 而且，在函数内部如果没有正确处理这些参数，也可能会引发错误。

提前将异常情况处理 ​

可以考虑提前将异常情况处理, 增强代码可读性, 减少代码复杂度

ts
private getCommandQueue(
  identifier: string,
  command: Command,
  concurrentCommandProcessing = false
) {
  let commandQueue = this._queues.serialQueue
  if (concurrentCommandProcessing) {
    if (
      'conversation_id' in command &&
      command.conversation_id !== '@legacy-conversation'
    ) {
      this._queues.createConcurrentQueue(command.conversation_id)
      commandQueue = this._queues.getConcurrentQueue(command.conversation_id)
    } else {
      commandQueue = this._queues.getConcurrentQueue(identifier)
    }
  }
  return commandQueue
}

private getCommandQueue(
  identifier: string,
  command: Command,
  concurrentCommandProcessing = false
) {
  if (!concurrentCommandProcessing) return this._queues.serialQueue

  const queueId =
    'conversation_id' in command &&
    command.conversation_id !== '@legacy-conversation'
      ? command.conversation_id
      : identifier
  if (!this._queues.getConcurrentQueue(queueId)) {
    this._queues.createConcurrentQueue(queueId)
  }
  return this._queues.getConcurrentQueue(queueId)
}

通常直接调用一个函数就可以执行相应的操作，而使用 setTimeout 并设置为立即执行（延迟时间为 0）似乎多此一举。

建议

若代码中, 在React组件中的确需要通过setTimeout的方式来实现某些功能, 应添加 [ 必要的详细说明 ]

在以下情况下可能会使用这种方式：

  1. 微任务队列与宏任务队列的利用

JavaScript 的事件循环中，微任务队列会在当前执行栈清空后立即执行，而宏任务队列中的任务会在微任务队列执行完后执行。setTimeout的回调函数会被放入宏任务队列。 当你希望在当前同步代码执行完之后，但在 React 进行下一次渲染之前执行某个函数时，可以使用这种方式。 比如: 在某些状态更新后，确保一些副作用在 React 处理完当前的更新周期后再执行。

  1. 解决特定的渲染问题： 有时候，React 的渲染机制可能会导致一些意外的行为。 例如，在某些连续的状态更新中，可能希望确保某个操作在 React 处理完一系列更新后再执行，以避免不必要的重复渲染或错误的状态读取。

  2. 与其他异步操作的协调： 如果你的代码中同时有其他异步操作，并且希望确保某个函数在这些异步操作完成后执行，但又不希望阻塞当前的执行流程，可以使用这种方式将其放入宏任务队列，等待其他异步操作完成后再执行。

总的来说，虽然这种用法**看起来不寻常**，但在特定的复杂场景下可以帮助开发者更好地控制代码的执行顺序和时机，以解决一些棘手的问题。 但同时也应该谨慎使用，因为过度使用可能会使代码变得难以理解和维护。

Zustand ​

Map & Set的使用 ​

如果你希望在更新数据后, 能够及时得到反馈(例如: 在React中, 及时更新组件数据), 那么, 在调用setState时, 需要通过对 Map 或 Set 赋值时, 通过new Map 或 new Set来修改其引用地址来实现.

js
import { create } from 'zustand'

const useFooBar = create(() => ({ foo: new Map(), bar: new Set() }))

function doSomething() {
  // doing something...

  useFooBar.setState((prev) => ({
    foo: prev.foo.set('newKey', 'newValue'),
    bar: prev.bar.add('newKey'),
  }))
}

尽量减少调用set函数的次数 ​

尽量减少调用set函数次数的主要原因有:

  • 减少不必要的重新渲染
    • 当set方法被调用时，Zustand 会通知所有订阅了该状态的组件进行更新。
    • 如果set方法被频繁调用，即使状态的实际变化很小或者对组件的显示没有实质性影响，也会导致组件频繁地重新渲染。
    • 例如，在一个包含大量子组件的复杂 React 组件树中，如果顶层的 Zustand 状态频繁调用set，那么整个组件树可能会经历多次不必要的重新渲染，这会消耗大量的计算资源并可能导致性能下降。
  • 保持状态的原子性
    • 减少set调用次数有助于保持状态更新的原子性。
    • 如果能够将多个相关的状态更新合并为一次set调用，就可以确保状态的改变是一个整体操作，而不是多个分散的、可能相互依赖的小操作。这有助于避免由于部分状态更新而导致的不一致性问题，例如: 数据竞争或者状态不一致的显示。

在 Zustand 中，可以通过以下几种方式来避免频繁调用set方法：

  • 合并多个状态更新
  • 使用条件判断来避免不必要的更新, 检查状态是否真正改变

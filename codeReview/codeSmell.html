Code Smell ​

当进行代码审查时，以下是一些常见的反面示例代码，涵盖不同类型的不良实践，以及针对每个问题点的修改建议

1. 不合理的命名和缩写 ​

反面示例： ​

javascript
function calcAmt(qty, prc) {
    let tot = qty * prc;
    return tot;
}

问题点： ​

  • 变量和函数名不清晰，使用了不必要的缩写。

修改建议： ​

使用清晰明了的命名，避免不必要的缩写，提高代码的可读性和可维护性。

javascript
function calculateTotalQuantity(quantity, price) {
    let totalAmount = quantity * price;
    return totalAmount;
}

2. 硬编码的值 ​

反面示例： ​

javascript
function calculateTax(amount) {
    return amount * 0.15; // 0.15 是硬编码的税率
}

问题点: ​

  • 硬编码的值使得代码难以维护和调整。

修改建议： ​

使用常量或者配置文件来管理这些值，提高代码的灵活性和可维护性。

javascript
const TAX_RATE = 0.15;

function calculateTax(amount) {
    return amount * TAX_RATE;
}

3. 长函数 ​

反面示例：

javascript
function processUserData(userData) {
    let processedData = [];

    // 获取用户信息
    let userInfo = fetchUserInfo(userData.userId);

    // 处理用户订单
    let userOrders = fetchUserOrders(userData.userId);
    userOrders.forEach(order => {
        if (order.status === 'pending') {
            order.items.forEach(item => {
                if (item.quantity > 0) {
                    item.actions.forEach(action => {
                        if (action.type === 'confirm') {
                            // 确认操作
                            confirmAction(action);
                        }
                    });
                }
            });
        }
    });

    // 生成用户报告
    processedData.push(generateUserReport(userData, userInfo, userOrders));

    return processedData;
}

问题点： ​

  • 函数过长，功能不明确，难以理解和维护。
  • 违反单一职责原则，应该将函数拆分成更小、更具体的函数。

修改建议： ​

拆分函数，每个函数专注于一个具体的任务或逻辑段落，提高可读性和可维护性。

javascript
function fetchUserData(userId) {
    // 获取用户数据
}

function processUserData({userId}) {
    // 处理用户数据
    const processedData = []
    ...
    return processedData
}

function generateReport(userData) {
    // 生成报告
}

function main(userData){
    const userData = fetchUserData(userData.userId);
    const processedData = processUserData(userData);
    const report = generateReport(processedData);
}
main()

4. 魔法数字和未清晰的命名 ​

反面示例： ​

javascript
function processOrder(order) {
    if (order.status === 1) {
        // 处理订单逻辑
    }
}

问题点： ​

  • 使用了魔法数字（例如：1），难以理解该数字的含义。
  • 变量或常量命名不清晰，不符合代码可读性的要求。

修改建议： ​

使用有意义的命名和常量来替代魔法数字，增强代码的可读性和维护性。

javascript
const ORDER_STATUS_PENDING = 1;

function processOrder(order) {
    if (order.status === ORDER_STATUS_PENDING) {
        // 处理订单逻辑
    }
}

5. 复杂的条件和嵌套逻辑 ​

反面示例： ​

javascript
function processOrder(order) {
    if (order && order.status === 'pending') {
        if (order.items && order.items.length > 0) {
            order.items.forEach(item => {
                if (item.quantity > 0 && item.status === 'available') {
                    // 处理订单项逻辑
                }
            });
        }
    }
}

问题点： ​

  • 嵌套层次过深，增加了代码的复杂性和理解难度。

修改建议： ​

使用早返回或者条件提前返回来简化嵌套逻辑，提高代码的可读性。

javascript
function processOrder(order) {
    if (!order || order.status !== 'pending' || !order.items || order.items.length === 0) {
        return;
    }

    order.items.forEach(item => {
        if (item.quantity > 0 && item.status === 'available') {
            // 处理订单项逻辑
        }
    });
}

6. 冗余的代码和重复逻辑 ​

反面示例： ​

javascript
function calculateAreaAndPerimeter(radius) {
    let area = Math.PI * radius * radius;
    let perimeter = 2 * Math.PI * radius;
    console.log('Area:', area);
    console.log('Perimeter:', perimeter);
}

问题点： ​

  • 相似的计算逻辑重复出现，增加了维护成本和代码复杂度。

修改建议： ​

将重复的逻辑提取为单独的函数或方法，避免代码重复。

javascript
function calculateArea(radius) {
    return Math.PI * radius * radius;
}

function calculatePerimeter(radius) {
    return 2 * Math.PI * radius;
}

function calculateAreaAndPerimeter(radius) {
    const area = calculateArea(radius);
    const perimeter = calculatePerimeter(radius);
    console.log('Area:', area);
    console.log('Perimeter:', perimeter);
}

7. 未处理的异常 ​

反面示例： ​

javascript
function fetchData(url) {
  try {
    fetch(url)
      .then(response => {
        if (!response.ok) {
          throw new Error('Network response was not ok');
        }
        return response.json();
      })
      .then(data => {
        // Process data
        console.log(data);
      });
  } catch (error) {
    console.error('Error fetching data:', error);
  }
}

问题点： ​

  • 这段代码中使用了 try-catch 块来捕获异常，但是 fetch 操作是异步的，所以 try-catch 块无法捕获 fetch 中的异常。
  • 如果 fetch 请求失败或返回的数据无法解析为 JSON，代码不会进行适当的错误处理。

修改建议： ​

  • 删除了 try-catch 块，因为 fetch 操作返回的 Promise 可以通过 .catch() 方法捕获异常。
  • 在最后添加了 .catch() 方法来处理 fetch 请求或 JSON 解析错误，并输出详细的错误信息。
  • 可以根据具体情况，采取适当的错误处理措施，比如显示用户友好的错误信息或进行其他恢复操作。

这样的修改可以更好地处理异步操作中可能发生的异常，并提高代码的可靠性和健壮性。

javascript
function fetchData(url) {
  fetch(url)
    .then(response => {
      if (!response.ok) {
        throw new Error('Network response was not ok');
      }
      return response.json();
    })
    .then(data => {
      // Process data
      console.log(data);
    })
    .catch(error => {
      console.error('Error fetching data:', error);
      // Handle error appropriately, e.g., show user-friendly message
    });
}

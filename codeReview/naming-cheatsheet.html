Code Rules ​

原文: https://github.com/kettanaito/naming-cheatsheet

在编码过程中, 取名字是一件很难的事情, 本文将尝试让它变得更容易些. 虽然这些建议可以用在任何编程语言中, 但我将在实践中使用JavaScript来说明它们.

English Language ​

命名变量和函数时, 应使用英语

ts
/* Bad */
const primerNombre = 'Gustavo'
const amigos = ['Kate', 'John']

/* Good */
const firstName = 'Gustavo'
const friends = ['Kate', 'John']

不管你是否喜欢, 英语是编程中使用的主要语言: 所有编程语言的语法/文档/教学资料等,都是使用英语编写的.

Naming convention(命名约定) ​

选择一种命名约定并遵循它, 它可以是:

  • camelCase
  • PascalCase
  • snake_case 或其他任何一种,只要保持一致即可. 许多编程语言在命名约定上都有自己的规则.
ts
/* Bad */
const page_count = 5
const shouldUpdate = true

/* Good */
const pageCount = 5
const shouldUpdate = true

/* Good as well */
const page_count = 5
const should_update = true

S-I-D ​

名称必须简短/直观,且具有描述性

  • Short, 简短, 一个名字不能花很长时间输入
  • Intuitive, 直观, 名字必须读起来自然, 尽可能接近日常用语
  • Descriptive, 描述性, 名称必须以最有效的方式来描述它的用途或内容.
ts
/* Bad */
const a = 5 // "a" could mean anything
const isPaginatable = a > 10 // "Paginatable" sounds extremely unnatural
const shouldPaginatize = a > 10 // Made up verbs are so much fun!

/* Good */
const postCount = 5
const hasPagination = postCount > 10
const shouldPaginate = postCount > 10 // alternatively

Avoid contractions (避免缩写) ​

不要使用缩写, 这样只会降低代码的可读性. 想找一个简短的/描述性的名称可能很困难, 但这并不是这样做的借口.

ts
/* Bad */
const onItmClk = () => {}

/* Good */
const onItemClick = () => {}

Avoid context duplication (避免上下文重复) ​

名称不应与定义的上下文重复, 如果不会降低名称的可读性, 那么可以考虑从名称中把上下文相关的单词删除掉.

ts
class MenuItem {
  /* Method name duplicates the context (which is "MenuItem") */
  handleMenuItemClick = (event) => { ... }

  /* Reads nicely as `MenuItem.handleClick()` */
  handleClick = (event) => { ... }
}

Reflect the expected result (反映预期结果) ​

名称应该能够反映出预期的结果

ts
/* Bad */
const isEnabled = itemCount > 3
return <Button disabled={!isEnabled} />

/* Good */
const isDisabled = itemCount <= 3
return <Button disabled={isDisabled} />

Naming functions (函数命名) ​

命名函数时, 可以遵循一个有用的公式:

prefix? + action (A) + high context (HC) + low context? (LC)

参考以下表格, 看看如何应用它.

NamePrefixAction(A)High context(HC)Low context(LC)
getUsergetUser
getUserMessagesgetUserMessages
handleClickOutsidehandleClickOutside
shouldDisplayMessageshouldDisplayMessage

注意: 上下文的顺序会影响变量(名称)的含义. 例如: `shouldUpdateComponent` 表示您即将更新组件，而 `shouldComponentUpdate` 告诉您组件将自行更新，而您仅控制其何时更新。换句话说，高上下文强调变量的含义。

Action ​

action是函数名称的动词部分, 也是最重要的部分, 它负责描述函数的功能.

get ​

立即访问数据(即内部的数据)

ts
function getFruitCount(){
  return this.fruits.length
}

另请参阅 compose

如果函数有执行异步操作, 也可以使用get作为前缀

ts
async function getUser(id){
  const user = await fetch(`/api/user/${id}`)
  return user
}

set ​

以声明的方式设置变量值, 将值 A 设置为值 B

ts
let fruits = 0

function setFruits(nextFruits){
  fruits = nextFruits
}

setFruits(5)

console.log(fruits) // 5

reset ​

将变量值恢复为初始值

ts
const initialFruits = 5
let fruits = initialFruits
setFruits(10)
console.log(fruits) // 10

function resetFruits(){
  fruits = initialFruits
}

resetFruits()
console.log(fruits) // 5

remove ​

移除某些事项

例如, 如果你在搜索页面上选定一组过滤器, 如果需要删除其中一个过滤器, 其名称应该用 removeFilter, 而不是deleteFilter.

ts
function removeFilter(filterName, filters){
  return filters.filter(name => name !== filterName)
}

const selectedFilters = ['prices', 'size']

另请参阅 delete

delete ​

彻底删除某些东西

想像一下, 您是一个名内容编辑人员,并且您希望删除一个臭名昭著的帖子. 一旦您点击了"删除帖子"按钮, cms就会执行deletePost操作, 而不是 removePost.

ts
function deletePost(id){
  return database.find({id}).delete()
}

另请参阅 remove

remove or delete ? ​

当你觉得 remove 和 delete 之间的差异不是很明显时, 我建议你看看与它相反的操作: add & create.

  • add, 需要目的地, 即你需要把新增的项添加到某个地方去.
  • create, 不需要目的地, 即 不需要与某个方匹配, 直接创建即可. 我们可以把 remove & add 映射, 将delete和create映射即可.

compose ​

从现有数据创建新的数据, 主要适用于字符串/对象或函数

ts
function composePageUrl(pageName, pageId){
  return pageName.toLowerCase() + '-' + pageId
}

另请参阅 get

handle ​

处理函数, 通常使用在回调方法的命名上, 比如: clickHandle

ts
function handleLinkClick(){
  console.log('Clicked a link!')
}

link.addEventListener('click', handleLinkClick)

Context ​

函数运行时的上下文

一个函数, 通常是对某个事物的操作. 重要的是: 说明它能够操作的区域是什么, 或者预期的数据类型

ts
/* A pure function operating with primitives */
function filter(list, predicate){
  return list.filter(predicate)
}

/* Function operation exactly on posts */
function getRecentPosts(posts){
  return filter(posts, (post) => post.date === Date.now())
}

Prefixes ​

前缀, 可以增加说明变量的含义, 但它一般很少在使用在函数名称中

is ​

一般用于描述当前上下文的特征或状态(通常是 boolean值)

ts
const color = 'blue'
const isBlue = color === 'blue'
const isPresent = true // state

if (isBlue && isPresent){
  console.log('Blue is present!')
}

has ​

描述当前上下文是否具有特定的值或状态(通常是boolean值)

ts
/* Bad */
const isProductsExist = productsCount > 0
const areProductsPresent = productsCount > 0

/* Good */
const hasProducts = productsCount > 0

should ​

肯定的条件语句(通常是boolean值), 通常与特定操作结合.

ts
function shouldUpdateUrl(url, expectedUrl){
  return url !== expectedUrl
}

min / max ​

表示最小值 / 最大值, 主要用于描述边界值

ts
/**
 * Renders a random amount of posts within the given min/max boundaries
 */
function renderPosts(posts, minPosts, maxPosts){
  return posts.slice(0, randomBetween(minPosts, maxPosts))
}

prev / next ​

表示当前上下文变量中的前一个或后一个状态, 主要用在 状态转换 场景时使用.

ts
async function getPosts(){
  const prevPosts = this.state.posts

  const latestPosts = await fetch('...')
  const nextPosts = concat(prevPosts, latestPosts)

  this.setState({posts: nextPosts})
}

Singular and Plurals (单数和复数) ​

与前缀一样, 变量名可以是单数或复数, 具体是哪个, 取决于它们是包含单个值或多个值

ts
/* Bad */
const friends = 'Bob'
const friend = ['Bob', 'Tony', 'Tanya']

/* Good */
const friend = 'Bob'
const friends = ['Bob', 'Tony', 'Tanya']
